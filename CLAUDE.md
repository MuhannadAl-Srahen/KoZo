# KoZo — project map for Claude

Local-first Windows game tracker: Electron 41 (main, CommonJS) + React 19 / Vite 8 (renderer, ESM) + better-sqlite3. Tracks playtime, sessions and achievements (Steam + cracked-game emulators), with a game overlay. Read this first; open only the files a task needs.

## Commands
- `npm run dev`: Vite on :5173 + Electron (`concurrently`). Electron runs through `scripts/dev-electron.js`, which restarts it (clean quit via the `kozo:dev-restart` IPC message) whenever the content of a file in `electron/` changes, so main/preload edits always apply. A change to the runner itself needs `npm run dev` started again. Dev also opens DevTools and runs React's dev build, so never judge in-game FPS from it.
- `npm run rebuild`: rebuild better-sqlite3 for Electron 41.7.1. Run it after `npm install` or the DB won't load.
- `npm run build`: `scripts/gen-icon.js`, then `vite build` (into `renderer-dist/`), then electron-builder (into `release/`).
- The builder config is `package.json` `"build"` (the only one; it sets the NSIS desktop shortcut and the GitHub publish target that electron-updater reads).
- `node scripts/test-parsers.js`: unit checks for the crack and achievement file parsers, the Epic/GOG/Xbox parsers, Pick for me scoring and Discord (against a fake pipe).
- `node scripts/test-backup-copy.js`: backup copy, restore rules and cloud folder detection.
- VS Code's terminal sets `ELECTRON_RUN_AS_NODE=1`, so run Electron through `env -u ELECTRON_RUN_AS_NODE` there, or `require('electron')` fails with "Cannot find module".
- `npm test` = parsers + `vite build` + `electron scripts/smoke-test.js`: the real app on a throwaway profile (own userData, `KOZO_RENDERER=dist` loads `renderer-dist`): every page, right-click menus, narrow width, controller across page changes, Pick for me, Big Picture. CI runs it before publishing.
- `SMOKE_ONLY=upcoming,tray,... electron scripts/smoke-test.js` runs only those parts of the smoke test (start and seeded library always run; parts: pages edit backups gamelist year sessions toolexe drive privacy version wishlist upcoming review appearance narrow controller pick big steamcopy update playthrough tray). After a change run only the parts it touches: the maker asked firmly not to rerun all ~290 checks each time.
- `npx vite build && electron scripts/perf-check.js`: speed check (development only; `scripts/` isn't in the installer). The real app off screen, muted, no network, on a throwaway profile with a pretend library of 500 games, 30,000 sessions and 20,000 achievements (the same every run, seeded), or `PERF_REAL=1` a copy of yours with keys stripped. Prints start time, each page's time to show and to stop moving, every request to the background process (slowest first) and every freeze of it over 80 ms, Library scroll frames, memory after a forced clean-up, and the Finished / Year review / XP / Library list query times with a fingerprint of their answers. `PERF_START_ONLY=1` only the start (compare a few runs, alternating builds: one run swings 0.3 s), `PERF_PROFILE=1` the start's slowest functions, `PERF_OUT=file.json`. Measure before and after a speed change, never guess.
- CI: `.github/workflows/release.yml`. Runs on `v*` tags, using bun on windows-latest, and publishes a GitHub release that electron-updater reads.
- Release notes: `build/release-notes.md`, first line `KoZo <version>`. electron-builder puts it in `latest.yml`, and `release.yml` puts it on the GitHub release, which is what KoZo's "What's new" shows after an update. Rewrite it for every release: notes naming another version are left off (1.9.0 and 1.9.1 went out with none, so people saw only "Bug fixes and improvements.").

## Layout
```
electron/            main process (CommonJS)
  main.js            boot, main window, kozo:// protocol, hotkeys, quit flush
  ipc.js             ALL ipcMain handlers (require-time registration)
  preload.js         contextBridge → window.kozo.api / window.kozo.events
  overlayWindow.js   transparent always-on-top overlay window (overlay.html)
  tray.js, appIcon.js, logger.js
  db/database.js     open/recover DB, runMigrations()
  db/schema.sql      CREATE TABLE IF NOT EXISTS …
  db/queries/*.js    games, sessions, achievements, gameList, customLists, settings
  services/*.js      background services (see below)
src/                 renderer (React)
  main.jsx           App (overlay.html → overlay-main.jsx → OverlayApp)
  App.jsx            HashRouter + Sidebar + global prompts/modals
  pages/  components/{ui,modals}/  context/  lib/  styles/
```

## Landing page (`site/`)
Plain HTML, CSS and JS with no build step, published to GitHub Pages at `kozoapp.cloud` by `.github/workflows/site.yml` (the domain is set in the repo's Pages settings, a CNAME file is ignored with a workflow; steps in `docs/google-drive.md`). Not part of the app: `build.files` leaves it out and nothing in `electron/` changes for it. WebGL can't read `file://` images, so view it over a local server.
- **Files:** `index.html`, `privacy.html` and `terms.html` (the addresses given to Google, so don't rename them), `css/site.css`, `js/hive.js` (the honeycomb: WebGL2, one instanced draw call, one image of covers), `js/game.js` (achievements, XP by the app's formulas, toasts, the session timer, colors, the Animations switch, fitting titles), `js/sections.js` (the dive, playground, session chart, Scan PC, rail, tiers, looks, restore points, controller, ending), `js/smooth.js` (the wheel glides instead of jumping, and links to a part of the page glide there; touch, keys and the scrollbar stay native; off with Animations off). Screenshots come twice: 2000 px in `assets/shots` and 1200 px in `assets/shots/sm`, picked by `srcset`/`sizes`; a new one needs both, and the look switcher sets `srcset` too, or the picture never changes. Every app screenshot exists in all 12 accent colors (Lime in `assets/shots`, the rest in `assets/shots/<color>/`, `SHOT_DIRS` in game.js): picking a color (or a look) swaps every screenshot's `srcset`, so the app on the page is the page's color (the maker's call); `look-*` pictures keep their own. `site-shots.js` waits until nothing is loading (no skeleton, every picture drawn) before each shot and fails the run rather than save a half-loaded one (the Discounts shot went up as skeletons); `SHOTS_COLORS` / `SHOTS_ONLY` narrow a run. The Download buttons read GitHub's latest release on each visit (kept 10 minutes per tab), and the size line stays hidden until GitHub answers.
- **Tools:** `scripts/site-assets.js` (fonts, favicon, cover image, the playground's picture, the share picture `og.jpg`, `ASSETS_ONLY=small` remakes the 1200 px screenshots), `scripts/site-shots.js` (real screenshots from the real app on a throwaway sample library, needs a fresh `vite build`; rerun when the app's look changes), `scripts/site-check.js` (15 sizes from 3440 wide to 320, real clicks and taps, words, links, weight, speed; run it after any change to the page).
- **Words, the maker's calls:** never say KoZo is free, because it won't stay free. Never "cracked": "games with no launcher at all, including achievements from emulators like Goldberg and CODEX", and no Cracked tag in screenshots. Never OneDrive. Don't promise Sign in with Google until the Google app is published. No made-up numbers or reviews. No long dashes.
- **Motion is the page's own setting** (`html[data-motion]`, the switch in the color panel), like the app's: the maker's Windows has animations off, and obeying it hid the whole page's movement. Someone whose system asks for less is told once where the switch is. `html.flat` (Animations off, or 880 wide and under) replaces the pinned scenes with plain stacked ones.
- **Traps:** a title is fitted by measuring, so `.measuring` must hold each line at its real width with nothing moving: a resize landing in the moment the letters were packed made the headline three times too wide on phones. `.stage` needs `overflow: clip`, because a sticky box with a negative margin can leave its parent and cover the next section. Each `.beat` needs `isolation: isolate`, or an earlier caption shows through a later screen. In `site-check.js`, attaching the debugger before a page has loaded takes the whole app down, and `Input.synthesizeTapGesture` never produces a click off screen, so taps are `Input.dispatchTouchEvent`.

## Main process
**Boot (`main.js` `whenReady`):** register `kozo://`, then `initDatabase()`, then `require('./ipc')`, then `createWindow()`. After that it starts processWatcher and crackWatcher, registers the Alt+K hotkey, and starts `autoBackup.startPeriodic()`. Delayed jobs are gated by `processWatcher.runWhenIdle` (they never run while a game is running): genre backfill, install check, privacy recheck, startup catch-up. Then releaseWatch, appUpdater, and the tray.
**Quit:** `will-quit` (and the window `session-end` event, for Windows shutdown) stops the watchers, flushes autoBackup and autoSaveBackup, then closes the DB.
**Main window** only hides on close, and is destroyed after 60s hidden to free RAM. Get it with `getOrCreateMainWindow()`; never keep a reference to it.

**IPC conventions**
- Channels are named `domain:action` (`games:add`, `steam:refresh`).
- Register a handler with `handle(channel, fn)` in `ipc.js`. It always resolves to `{ ok: true, data }` or `{ ok: false, error }` and never rejects, so renderer code must check `res?.ok`.
- Push events with `broadcast(channel, payload)`, which goes to all windows.
- **Adding an API = a handler in `ipc.js` + a method in `preload.js`** (`api.<domain>.<method>` → `ipcRenderer.invoke`). Event subscriptions are `events.onX(cb)` and return their own unsubscribe function.

**Database:** `%APPDATA%\KoZo\kozo.db`, WAL, `foreign_keys=ON`. Logs go to `%APPDATA%\KoZo\logs`.
- Tables: games, sessions, achievements, achievement_unlocks, game_list, custom_lists, custom_list_games, settings (key/value), scan_folders, categories (legacy).
- Migrations have no version number. `runMigrations()` runs `ALTER TABLE … ADD COLUMN` statements in try/catch, plus one-time steps guarded by flags stored in settings. **New column → add it as an `ALTER TABLE … ADD COLUMN` in `runMigrations()`** (`schema.sql` holds only the original columns).
- better-sqlite3 refuses JS booleans, so flags must be 0/1 (`flag()` in `queries/games.js`). Named params (`@x`) throw if the key is missing.

**Services (`electron/services/`)**

`processWatcher` is the hub. Every unlock source ends up in `achievementSync.emitNewUnlocks()`, which updates the DB, the overlay toast, XP and the backup. Disk-heavy work checks `processWatcher.isSessionActive()` first, or wraps itself in `runWhenIdle`. Deferred jobs drain one at a time (20s after the last game closes, then 4s apart), and the after-play save backup waits 30s: running everything the instant a game closed made the whole PC stutter. `beforePlay` runs at most once per 2 minutes per game (launch and session start) with lighter gzip (level 5).

| Service | Role |
|---|---|
| processWatcher | Polling loop: 5s while playing, 20s idle. Detects games, opens and ends sessions, AFK/idle pause, sleep gaps, crash recovery, unknown-exe prompt. Events: `session:*`. |
| achievementSync | Steam unlock sync: on launch, every 10s while playing, and on session end with retries. Achievement list (schema) fetch, private-profile state. `sweepSteamGames` (startup catch-up, each game at most every 12h, setting `ach_sweep_at`): refreshes each list weekly (`ensureSchema({ refresh })` upserts new achievements from game updates; every sweep while a game has none) and imports Web API unlocks (catches ones earned on other PCs). An unlock whose achievement isn't in the stored list triggers a list refresh first. |
| steamApi / steamOpenId | Steam Store and Web API (axios), banner download, genres; Steam login on a local 127.0.0.1 listener. |
| steamStatsWatcher, binaryKV | Read local `appcache\stats\UserGameStats_*.bin` (binary KeyValues format). |
| crackWatcher, crackDiscovery | Emulator achievement files (Goldberg, CODEX, …): chokidar per game, a 60s safety net, a deep scan when idle. A Goldberg game without `steam_settings/achievements.json` gets it written automatically once per run (`enableGoldbergAchievements`, also for the ColdClient loader layout: steamclient64.dll + ColdClientLoader.ini). In `diagnoseGame`, an INI holding only `[SteamAchievements] Count=` is "nothing saved yet", not an unreadable format. |
| xp, xpTracker | XP is a pure function of the DB; the tracker emits `xp:levelup` and the overlay toast. Rules (the maker asked for rarity to matter, and more ways to earn): 60 per hour; an unlock by its rarity band, the bands KoZo names everywhere (`RARITY_XP`: Common 55, Uncommon 80, Rare 120, Very Rare 250, Ultra Rare 500, unknown 55; no unlock is worth less than under the old 30 + (100 - %)/2, so no level goes down, tested); 100% a game 10 per achievement (100 to 1,000); 250 per finished game and per playthrough finished again with an hour played in it; milestones (10/25/50/100 hours in one game, 50 per game played an hour, 100 per game finished in its Play Plan month, by its first finish); 50 per day of the longest streak. Unlock XP is counted in SQL (`unlockXpSql`, the same rule for Recent XP); the play days for the streaks are kept until the sessions' fingerprint changes. `computeXp` returns `byRarity`, `replayCount`, `milestones` and `rules` (Profile's "How XP works" and its rarity row read them, so the guide can't drift). Changing a number means a new `XP_RULES`: main.js then moves the tracker's baseline once (`xpTracker.rebase`), or the next session would show the whole difference as gained. The unlock toast says the band ("Ultra Rare · +500 XP"). The site's playground (`site/js/game.js` `xpFor`) uses the same numbers. |
| playthroughs | Playing a game again (the maker: "a second playthrough"): `db/queries/playthroughs.js`, table `playthroughs` (game_id, number, started_at, finished_at). No rows = the first playthrough. The game page's menu "Start a new playthrough" (`games:newPlaythrough`, asks first, then 20 s Undo via `ui/UndoBar`, `games:undoPlaythrough` puts the status and its date back) adds row 1 from the first session, closes the current one (finished if the game was finished during it) and opens the next; the game goes back to Playing (`setGameStatus`, no rating window). Hours, sessions and unlocks are never touched: a session belongs to the playthrough it started in, so each one's time comes from the sessions (`playthroughStats` in GameDetail). The current playthrough's finish isn't stored: it's the game's Finished status set after it began. The Overview shows a Playthroughs card and Your stats the current one's time once there are two. Starting one moves no XP (the first finish still counts, `allFinishes`). In backups and restores (autoBackup `TABLES`, `importBackupFile`); another PC's library merge doesn't bring them. |
| saveDetect, saveManifest, saveFinder, saveVault, autoSaveBackup, backupHome, googleDrive | Game-save backups, no clicks needed. `saveDetect` finds each game's saves itself and CONFIRMS them (`games.save_paths`, JSON): the Ludusavi manifest (`saveManifest`, downloaded weekly, worker parse, `pathsFor` expands placeholders), emulator folders by app id (from `crackWatcher.buildCandidates`, the `remote` subfolder when there is one), Steam Cloud `userdata/<u>/<appid>/remote`, and after each session the folders the game wrote to (`learnFromSession` → pure `pickChangedFolders`); `confirmAll` at startup and when the Backups page opens. A found folder holding over 1 GB of non-junk files is never confirmed (`saveBytes`); `isJunk` also drops game data (exe, dll, pak, ucas/utoc, Mods, Binaries, Content, texture caches). `saveFinder` name guesses are only suggestions in the per-game window. `saveVault`: per game `<root>/<Game>/vault/{blobs/<sha1>.gz, snapshots/<id>.json}`, dedupe + gzip, junk left out (`saveDetect.isJunk`: logs, caches, dumps, video), skipped under 2 GB free, verified writes, smart prune (`prunePolicy`: all for 7 days, daily to 30, weekly to 90), exact restore (staged swap, before-restore snapshot; refused while that game is running; a crack's save folder from before an update is written to the current crack's, `targetsFor` via crackSaves, for `compare` too), cap `save_vault_cap_gb` (default 2 GB, `capGb`); single files over 256 MB skipped; gzip level 9; reads (`listSnapshots`, `usage`) never create folders (`existingVault`), `cleanEmpty` removes empty ones at startup. Before-play (doLaunch, session start, 4s budget) and after-play snapshots. `backupHome` picks where everything lives: `backup_base` = `<other fixed drive>\KoZo Backup` (most free space) else `Documents\KoZo Backup`, with `Saves` and `Data` inside; a folder in Temp/Downloads/Desktop is moved out on startup (`ensure`, also turns automatic backups on once, flag `backup_defaults_v1`); `findExisting` finds old KoZo Backup folders for a restore. `googleDrive` (`docs/google-drive.md`): the off-PC copy, shown (Connections row, Backups place, "Sign in with Google") only when a client exists, never a setup step for users (OAuth loopback + PKCE, scope drive.file, folder "KoZo Backup", files named by path, refresh token encrypted with safeStorage in `gdrive_token`), the Google client comes from settings `gdrive_client_id`/`gdrive_client_secret` (pasted in `components/DriveSetupModal.jsx`, opened from Connections > Advanced > "Use your own Google client"; local only, never exported), else `GOOGLE_CLIENT_ID/SECRET` in `electron/defaults.js`; `sync` after a backup (idle only) uploads what Drive lacks, stays inside `gdrive_budget_gb` (default 1; 0.5 / 1 / 2 / 5) and the real quota by leaving old automatic restore points out (pure `cloudPrunePlan`), never touches the local copy, only deletes on Drive what this install uploaded (`userData/drive-state.json`); each install has its own library file there (`Data/kozo-library-<install_id>.json`; the old shared `Data/kozo-autobackup.json` is still read, never written); `restoreDown` brings down only the save backups that are missing (free space checked first, waits while a game runs), then `saveBackup.adoptFolders` gives each folder this PC's game id. |
| exeCheck | Is this exe a game? Reads the import table from the file's bytes (a few small reads, nothing is started): pure `loadsGameParts` (graphics, game sound, controller, `steam_api`), `engineBeside` for an engine's starter (UnityPlayer.dll, `<exe>_Data`, a .pck). Measured on real folders: AlienShooter, Atomic Exile, HallsOfTorment and gamemd-spawn pass; Options_INI_Helper, Syringe, CnCNetQM, the CnCNet clients and installers don't. A real starter can load none of it ("Halls of Torment.exe"), so no sign alone never rejects a file: it only means "not sure". |
| launchCheck | Play was pressed and the watched file never started, so the play isn't being counted: after 45s (Steam launches never; store launchers 2 min; never while a session is active, and not once the game was detected, even if it closed again) a corner card asks which program it is (`components/LaunchMissCard.jsx`, the user's choice over a window), plus a toast (`launchMiss:overlay`) when KoZo isn't in front, since that may be the game. Not asked when a launcher started it and the watched file is a real game file: it's waiting in the launcher's menu. Pure `candidatesFor`: only a running exe in the game's own folder that passes `exeCheck`. "What started since Play" was offered once and suggested smartscreen.exe (Windows starts it for a permission prompt) and an online client, and the user picked them, so anything else is under All programs. `choose` refuses Windows programs (`HARD_DENY`). No PowerShell until someone picks a program. A pick sets `exe_name`/`install_path`; what KoZo started stays as `launch_file` unless it's gone or a tool (pure `launchAfterPick`). "Not now" twice for a game stops asking (`launch_miss_dismissed`). |
| libraryMerge | Another PC's backup comes in by merging, never by id: game 5 on one PC is a different game on another. Signing in with an account that holds another PC's backup asks THREE separate questions, one after another (the user's explicit call, not one window of ticks): Game List, then Library, then game saves; a question with nothing new is skipped, and closing the window stops them (`components/DriveOffer.jsx`, `drive:offer` event, `api.drive.offer` / `applyOffer({ step, restoreLook })`). Also from Backups > Get everything back > Google Drive and the first-run RestoreOffer; there is no `drive:restore` any more. After sign-in, another PC's new things show as a bar at the top (`components/DriveNewsBar.jsx`, the user's choice over a window): looked for 90s after start and hourly, never during a game; `googleDrive.remoteStamp` means nothing is downloaded unless the other PC's files changed; pure `newsSince` says it once per new thing (`drive_news_seen`, comes down when counts do); "See what's new" opens the three questions, and any look at them counts as seen. Pure `planMerge` + `applyPlan` (one transaction): a game matches by Steam id, then name; everything gets this PC's ids; a matched game keeps its folder, exe and status and only fills empties; sessions add unless the same start time exists, playtime grows only by what was added; open sessions are skipped; the earlier unlock wins; a second run adds nothing; `xpTracker.rebase` so no level-up toast. `importBackupFile` merges whenever the file came from another install and this library isn't empty (`.kozo`, folder restores), without the questions. `saveVault.mapSource` moves `C:\Users\<other>\` in a restore point to this PC's home, and a restore refuses a drive that isn't here. Test with `scripts/fake-drive.js` (the real googleDrive.js against a pretend Drive; smoke test's Google block). |
| autoBackup | JSON dump of the DB tables to `auto_backup_dir` (`<backup_base>\Data`). Debounced after changes, every 5 min, and a synchronous flush on quit. Each file carries this install's `install_id`; a file another install wrote is renamed beside (`kozo-autobackup-<date>-<id>.json`), never overwritten, so a fresh Windows can still restore it (first run offers it: `components/RestoreOffer.jsx`). |
| backupCopy, cloudFolders | A copy of the backups in a folder the user picks (`backup_copy_dir`, `<folder>\KoZo Backup`, same `Saves\` + `Data\` layout as local): Google Drive for Desktop, Dropbox, MEGA or iCloud folders found on the PC, or any folder or USB stick. OneDrive is never offered (maker's choice). It is a copy, never a move: restoring from one (`backup:restoreFolder(path, { copy: true })`) must not call `setBase`. Save files go through saveVault's mirror (`syncMirror`, async, pauses while a game runs); `autoBackup` copies the library file. |
| kozoPack | One file with everything (`.kozo`): "KOZOPACK1\n", a 4-byte index length, JSON index, then raw bytes, streamed both ways; `data.json` (autoBackup's payload) + `Saves/**` (the vault; existing blobs kept on import, `..` paths refused). IPC `pack:export` / `pack:import` (+ `pack:progress`), Backups "Save to a file" / "From a KoZo file", also on the first-run RestoreOffer |
| statusSync, installCheck | Keep game status and list status in step (`undoSessionStart`: a session under a minute takes back the status and dates it set, so a game isn't "Not played yet, last played 1m ago"); update the installed flag and relocate moved games. `reconcile` runs at start, when the main window gets focus (at most every 15s) and every 5 min, never during a session; `quick` only hunts for a new location the moment a game goes missing. A folder isn't a game: pure-ish `hasGameFile` wants a file that can start it, because uninstallers leave saves behind. |
| releaseWatch | Refreshes tracked upcoming games' Steam dates (delays), then flags released ones: overlay toast once, plus the `unseen_releases` setting behind the "Now out" panel (`ReleasedPanel`) and the Upcoming sidebar badge. Runs at startup, every 6h, and when the main window is shown. |
| statusFlash (Alt+K) | Overlay info panel. |
| desktopProbe | The ONE hidden PowerShell process for what Node can't ask Windows (compiled once at start, so nothing spawns or compiles during a game): controller wake combo, controller activity, app in front. Runs while any of those is on, checked on every watcher tick. Reads a controller slot every 120 ms but an empty slot only every 2 s (Microsoft's XInput guidance). |
| foregroundProbe | The app in front, from desktopProbe. Two uses: `away_pause_sec` (Settings > Tracking, default 60, 0 = off; pure `isGameWindow` and `awaySeconds`; pauses through the same `session.idle` path as AFK and takes back the whole span, so shorter switches still count; a game never seen in front on this PC never pauses (setting `front_seen_games`, kept across restarts), and an unknown front app never takes time off) and telling the main window it isn't in front (`app:inFront`). |
| controllerInput | When a controller was last used (reported by desktopProbe), so controller play doesn't count as AFK. AFK (`idle_pause_min`, default 5) is applied in `processWatcher.heartbeatSession`: the tick that first flags AFK subtracts the whole quiet span since the last input, not only the part past the threshold. |
| breakReminder | Settings > Tracking > Break reminder (`break_reminder_min`, default 0 = off). Pure `breakDue`, called from `heartbeatSession` with no timer of its own: active time only, waits while paused, quiet after a restart or a changed interval. Toast `break:overlay`, no chime. |
| steamNews | The developer's own announcements for a game's page (`feeds=steam_community_announcements`: without it a popular game's feed is mostly outside sites, in any language). Cached 3h, fetched only when a page opens. Pure `newsBlocks` turns Steam's markup into text blocks, never HTML. Only known tags are removed: patch notes are full of plain words in brackets like `[Console]`. |
| gameVersion | The version tag beside a game's name (`games:version`, only when a game page opens; no process, the exe's version resource is parsed from its bytes). This copy: emulator build (`steam_settings/branches.json`, `build_id.txt`) or Steam manifest, else the exe's version unless it's the engine's (`ENGINE`, Unreal stamps its own), else the folder name, else the exe's date. Steam's newest: `api.steamcmd.net` (build + date, third party, cached 6h) and the number in the newest patch notes' titles (`newsFacts`). A loader (`ColdClientLoader.ini` `Exe`/`ExeRunDir`, or `steamclient64.ini` `Target`/`StartIn`, pure `loaderTargetFromIni`) is followed to the program it starts, so the tag describes what Play really runs. The same file installed more than a day later elsewhere in the folder (pure `pickNewerCopy`, by creation time) comes back as `newerCopy`; the game page says "A newer copy was installed on ..." with Use the new copy (`games:useCopy`: an exe inside the game folder only, set as `launch_file` and `exe_name`). Pure `versionState`: builds or numbers say `behind`/`current`; dates only ever say `maybe`, because an update may not touch the exe and another store's copy has its own dates. |
| wishlist | Steam wishlist into the Game List, only when the user presses the button (`gameList:wishlistPreview` / `wishlistImport`, `WishlistImportModal`). `IWishlistService/GetWishlist` needs no key; an empty and a private wishlist look the same. Unreleased games become Upcoming. No per-game network calls, so a long wishlist comes in at once; genres follow from the idle backfill. |
| discordPresence | Discord Rich Presence over the local pipe (no package), settings `discord_presence` + `discord_client_id` (the user's own Discord app). Driven by `processWatcher.onChange`; connects only while a session is active, retries at most once a minute. |
| launcherImport | Reads Epic manifests, the GOG registry (or `goggame-*.info`) and Xbox packages (`powershell.exe` Get-AppxPackage + MicrosoftGame.config). Part of Scan PC: `scanner:scan` merges them (pure `mergeLauncherGames`: a game in both is the launcher's, which knows how to start it); there is no separate button (the user's call). On launch an idle background pass broadcasts `launchers:found` for the Library strip (`launcher_seen` = reviewed keys). |

## Gotchas
- Database indexes (`runMigrations`, end): sessions by game and start, by start, unlocks by session, Game List by game and by Steam id. There were none, so the Finished page (two lookups per finished game) took 0.3 s and the Year review froze KoZo 0.7 s at 30,000 sessions; 2 ms and 0.05 s now (`scripts/perf-check.js`). A query that converts every row to local time (`DATE(x, 'localtime')`, `strftime(..., 'localtime')`) can't use them: narrow by a plain date range first (a day or two wider than the period, for time zones) and keep the exact local check on those rows (`IN_YEAR`, `dayWindow`, the hourly chart). With an index a tie can come back in another order: `ORDER BY duration DESC, id ASC` keeps "longest session" the same as before.
- SQLite trap: `sessions.started_at` and the other TIMESTAMP columns have numeric affinity, so a bound value like `'9999'` becomes the number 9999 and every date (text) sorts after it: `started_at < '9999'` was never true. Use full dates as open bounds (`'9999-12-31'`, `'0000-01-01'`).
- Nothing on the main process may wait on another program when it can be asked without waiting: `execSync`/`execFileSync` froze KoZo for the whole call (the startup task check about 0.1 s on every Settings > General, the drive list 0.3 to 0.7 s, the Steam folder and Documents lookups 50 and 40 ms at every start). They use `execFile` now (`runQuiet` in ipc.js, `backupHome.fixedDrivesAsync`, `steamStatsWatcher.warmSteamPath`, Documents from `app.getPath('documents')`), and the app icons are drawn once and kept in `<userData>/icon-cache` (`appIcon.js`, bump `ICON_VERSION` when the drawing changes): drawing them took 0.3 s of every start.
- Code splitting by page was measured (React.lazy for every page but the Library, all preloaded when idle): the main file went from 641 KB to 172 KB but the start wasn't faster (alternating runs, 1.30 against 1.34 s) and memory only 3 MB lower, because the files are read from the PC's own disk. Undone; don't redo it without a new reason.
- Library re-renders: `GameCard` is `React.memo`, so its handlers must stay the same between renders (`useCallback`: `toggleGame`, `handleFavorite`, `openCardMenu`) and its game objects too (`allGamesWithLive` is `useMemo`); an inline arrow or a fresh object made every card redraw when a menu opened. The sidebar's Now Playing timer is its own component (`LiveElapsed`), so only it redraws each second.
- Sessions under 60 s (`MIN_SESSION_SEC`, queries/sessions.js) are deleted with their playtime at end and in orphan recovery, and send `session:discarded` (no toast, XP or notification).
- Launch order in `doLaunch`: `launch_file`, then `launch_uri` (Epic URI / `shell:AppsFolder\...` for Xbox), then the exe, then Steam. A game played through Steam (source steam, not is_cracked, a Steam id, no launch file or link) always goes to `steam://run/<id>`, never its file: started directly, Halls of Torment said "Could not initialize the Steam API" right after a switch to the Steam copy.
- Games start through `shellStart` (PowerShell Start-Process = ShellExecute), never a direct `spawn()`: a spawned game inherited KoZo's handles (sockets, pipes) and held them after KoZo quit.
- Settings → General → Graphics acceleration writes `gpu.json` in userData; main.js reads it before ready and calls `app.disableHardwareAcceleration()` (the fix for graphics drivers timing out with KoZo open). Big Picture minimizes KoZo after Play.
- Settings > Tracking > "Minimize KoZo when a game starts" (`minimize_on_play`, off by default): processWatcher minimizes the main window on the first sight of a game (`session:detected`), a couple of seconds after Play thanks to `nudge()`, and for games started anywhere else too.
- Windows startup passes `--startup`; "Start minimized" applies only then (or uptime < 3 min). The task is created from XML (battery, no time limit, normal priority; HighestAvailable, falling back to LeastPrivilege). The one-time `startup_v2` upgrade runs only when packaged.
- Pick for me = `lib/pickForMe.js` (pure) + `PickForMeModal` (Game List toolbar, Big Picture): all Want to play rows, +1 weight when planned this month.
- Sidebar: Play / Discover group titles (only while the tab order keeps groups together), live Now Playing card with the game's art, XP ring on the avatar. Appearance `sidebar: 'full' | 'rail'` (slim, icons only); the button by the logo switches.
- Release tracking is `game_list.release_watch` (not the status); a game released over 14 days ago is never watched or announced (`releaseWatch.isLongReleased`): Track / status Upcoming set it, other statuses keep it, `gameList:untrack` clears it (deleting the row only if still Upcoming). releaseWatch selects `release_watch = 1`.

- Ctrl + mouse wheel depends on the pointer: over a card grid (any element with the `useCardZoom` style, which always sets `--zoom-grid`) it resizes the cards; anywhere else, or over `[data-zoom-ignore]`, it changes the UI scale (`CtrlWheelZoom` in App.jsx, 80 to 150% in 5% steps).
