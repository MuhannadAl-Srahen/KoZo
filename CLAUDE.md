# KoZo — project map for Claude

Local-first Windows game tracker: Electron 41 (main, CommonJS) + React 19 / Vite 8 (renderer, ESM) + better-sqlite3. Tracks playtime, sessions and achievements (Steam + cracked-game emulators), with a game overlay. Read this first; open only the files a task needs.

## Commands
- `npm run dev`: Vite on :5173 + Electron (`concurrently`). Electron runs through `scripts/dev-electron.js`, which restarts it (clean quit via the `kozo:dev-restart` IPC message) whenever the content of a file in `electron/` changes, so main/preload edits always apply. A change to the runner itself needs `npm run dev` started again. Dev also opens DevTools and runs React's dev build, so never judge in-game FPS from it.
- `npm run rebuild`: rebuild better-sqlite3 for Electron 41.7.1. Run it after `npm install` or the DB won't load.
- `npm run build`: `scripts/gen-icon.js`, then `vite build` (into `renderer-dist/`), then electron-builder (into `release/`).
- The builder config is `package.json` `"build"` (the only one; it sets the NSIS desktop shortcut and the GitHub publish target that electron-updater reads).
- `node scripts/test-parsers.js`: unit checks for the crack and achievement file parsers, the Epic/GOG/Xbox parsers, Pick for me scoring and Discord (against a fake pipe).
- `node scripts/test-backup-copy.js`: backup copy, restore rules and cloud folder detection.
- VS Code's terminal sets `ELECTRON_RUN_AS_NODE=1`, so run Electron through `env -u ELECTRON_RUN_AS_NODE` there, or `require('electron')` fails with "Cannot find module".
- `npm test` = parsers + `vite build` + `electron scripts/smoke-test.js`: the real app on a throwaway profile (own userData, `KOZO_RENDERER=dist` loads `renderer-dist`): every page, right-click menus, narrow width, controller across page changes, Pick for me, Big Picture. CI runs it before publishing.
- CI: `.github/workflows/release.yml`. Runs on `v*` tags, using bun on windows-latest, and publishes a GitHub release that electron-updater reads.

## Layout
```
electron/            main process (CommonJS)
  main.js            boot, main window, kozo:// protocol, hotkeys, quit flush
  ipc.js             ALL ipcMain handlers (require-time registration)
  preload.js         contextBridge → window.kozo.api / window.kozo.events
  overlayWindow.js   transparent always-on-top overlay window (overlay.html)
  tray.js, appIcon.js, logger.js
  db/database.js     open/recover DB, runMigrations()
  db/schema.sql      CREATE TABLE IF NOT EXISTS …
  db/queries/*.js    games, sessions, achievements, gameList, customLists, settings
  services/*.js      background services (see below)
src/                 renderer (React)
  main.jsx           ?tray=1 → TrayApp, else App (overlay.html → overlay-main.jsx → OverlayApp)
  App.jsx            HashRouter + Sidebar + global prompts/modals
  pages/  components/{ui,modals}/  context/  lib/  styles/
```

## Landing page (`site/`)
Plain HTML, CSS and JS with no build step, published to GitHub Pages at `kozoapp.cloud` by `.github/workflows/site.yml` (the domain is set in the repo's Pages settings, a CNAME file is ignored with a workflow; steps in `docs/google-drive.md`). Not part of the app: `build.files` leaves it out and nothing in `electron/` changes for it. WebGL can't read `file://` images, so view it over a local server.
- **Files:** `index.html`, `privacy.html` and `terms.html` (the addresses given to Google, so don't rename them), `css/site.css`, `js/hive.js` (the honeycomb: WebGL2, one instanced draw call, one image of covers), `js/game.js` (achievements, XP by the app's formulas, toasts, the session timer, colors, the Animations switch, fitting titles), `js/sections.js` (the dive, playground, session chart, Scan PC, rail, tiers, looks, restore points, controller, ending), `js/smooth.js` (the wheel glides instead of jumping, and links to a part of the page glide there; touch, keys and the scrollbar stay native; off with Animations off). Screenshots come twice: 2000 px in `assets/shots` and 1200 px in `assets/shots/sm`, picked by `srcset`/`sizes`; a new one needs both, and the look switcher sets `srcset` too, or the picture never changes. The Download buttons read GitHub's latest release on each visit (kept 10 minutes per tab), and the size line stays hidden until GitHub answers.
- **Tools:** `scripts/site-assets.js` (fonts, favicon, cover image, the playground's picture, the share picture `og.jpg`, `ASSETS_ONLY=small` remakes the 1200 px screenshots), `scripts/site-shots.js` (real screenshots from the real app on a throwaway sample library, needs a fresh `vite build`; rerun when the app's look changes), `scripts/site-check.js` (15 sizes from 3440 wide to 320, real clicks and taps, words, links, weight, speed; run it after any change to the page).
- **Words, the maker's calls:** never say KoZo is free, because it won't stay free. Never "cracked": "games with no launcher at all, including achievements from emulators like Goldberg and CODEX", and no Cracked tag in screenshots. Never OneDrive. Don't promise Sign in with Google until the Google app is published. No made-up numbers or reviews. No long dashes.
- **Motion is the page's own setting** (`html[data-motion]`, the switch in the color panel), like the app's: the maker's Windows has animations off, and obeying it hid the whole page's movement. Someone whose system asks for less is told once where the switch is. `html.flat` (Animations off, or 880 wide and under) replaces the pinned scenes with plain stacked ones.
- **Traps:** a title is fitted by measuring, so `.measuring` must hold each line at its real width with nothing moving: a resize landing in the moment the letters were packed made the headline three times too wide on phones. `.stage` needs `overflow: clip`, because a sticky box with a negative margin can leave its parent and cover the next section. Each `.beat` needs `isolation: isolate`, or an earlier caption shows through a later screen. In `site-check.js`, attaching the debugger before a page has loaded takes the whole app down, and `Input.synthesizeTapGesture` never produces a click off screen, so taps are `Input.dispatchTouchEvent`.

## Main process
**Boot (`main.js` `whenReady`):** register `kozo://`, then `initDatabase()`, then `require('./ipc')`, then `createWindow()`. After that it starts processWatcher and crackWatcher, registers the Alt+K hotkey, and starts `autoBackup.startPeriodic()`. Delayed jobs are gated by `processWatcher.runWhenIdle` (they never run while a game is running): genre backfill, install check, privacy recheck, startup catch-up. Then releaseWatch, appUpdater, and the tray.
**Quit:** `will-quit` (and the window `session-end` event, for Windows shutdown) stops the watchers, flushes autoBackup and autoSaveBackup, then closes the DB.
**Main window** only hides on close, and is destroyed after 60s hidden to free RAM. Get it with `getOrCreateMainWindow()`; never keep a reference to it.

**IPC conventions**
- Channels are named `domain:action` (`games:add`, `steam:refresh`).
- Register a handler with `handle(channel, fn)` in `ipc.js`. It always resolves to `{ ok: true, data }` or `{ ok: false, error }` and never rejects, so renderer code must check `res?.ok`.
- Push events with `broadcast(channel, payload)`, which goes to all windows.
- **Adding an API = a handler in `ipc.js` + a method in `preload.js`** (`api.<domain>.<method>` → `ipcRenderer.invoke`). Event subscriptions are `events.onX(cb)` and return their own unsubscribe function.

**Database:** `%APPDATA%\KoZo\kozo.db`, WAL, `foreign_keys=ON`. Logs go to `%APPDATA%\KoZo\logs`.
- Tables: games, sessions, achievements, achievement_unlocks, game_list, custom_lists, custom_list_games, settings (key/value), scan_folders, categories (legacy).
- Migrations have no version number. `runMigrations()` runs `ALTER TABLE … ADD COLUMN` statements in try/catch, plus one-time steps guarded by flags stored in settings. **New column → add it as an `ALTER TABLE … ADD COLUMN` in `runMigrations()`** (`schema.sql` holds only the original columns).
- better-sqlite3 refuses JS booleans, so flags must be 0/1 (`flag()` in `queries/games.js`). Named params (`@x`) throw if the key is missing.

**Services (`electron/services/`)**

`processWatcher` is the hub. Every unlock source ends up in `achievementSync.emitNewUnlocks()`, which updates the DB, the overlay toast, XP and the backup. Disk-heavy work checks `processWatcher.isSessionActive()` first, or wraps itself in `runWhenIdle`. Deferred jobs drain one at a time (20s after the last game closes, then 4s apart), and the after-play save backup waits 30s: running everything the instant a game closed made the whole PC stutter. `beforePlay` runs at most once per 2 minutes per game (launch and session start) with lighter gzip (level 5).

## Gotchas
- Sessions under 60 s (`MIN_SESSION_SEC`, queries/sessions.js) are deleted with their playtime at end and in orphan recovery, and send `session:discarded` (no toast, XP or notification).
- Launch order in `doLaunch`: `launch_file`, then `launch_uri` (Epic URI / `shell:AppsFolder\...` for Xbox), then the exe, then Steam.
- Games start through `shellStart` (PowerShell Start-Process = ShellExecute), never a direct `spawn()`: a spawned game inherited KoZo's handles (sockets, pipes) and held them after KoZo quit.
- Settings → General → Graphics acceleration writes `gpu.json` in userData; main.js reads it before ready and calls `app.disableHardwareAcceleration()` (the fix for graphics drivers timing out with KoZo open). Big Picture minimizes KoZo after Play.
- Windows startup passes `--startup`; "Start minimized" applies only then (or uptime < 3 min). The task is created from XML (battery, no time limit, normal priority; HighestAvailable, falling back to LeastPrivilege). The one-time `startup_v2` upgrade runs only when packaged.
- Pick for me = `lib/pickForMe.js` (pure) + `PickForMeModal` (Game List toolbar, Big Picture): all Want to play rows, +1 weight when planned this month.
- Sidebar: Play / Discover group titles (only while the tab order keeps groups together), live Now Playing card with the game's art, XP ring on the avatar. Appearance `sidebar: 'full' | 'rail'` (slim, icons only); the button by the logo switches.
- Release tracking is `game_list.release_watch` (not the status); a game released over 14 days ago is never watched or announced (`releaseWatch.isLongReleased`): Track / status Upcoming set it, other statuses keep it, `gameList:untrack` clears it (deleting the row only if still Upcoming). releaseWatch selects `release_watch = 1`.
- Marking a game Finished (statusSync `setGameStatus` or `gameList:update`) broadcasts `game:finished`; App.jsx opens `RateGameModal` (1 to 10, `gameList:rate`, stored on the Game List row).
- Ctrl + mouse wheel depends on the pointer: over a card grid (any element with the `useCardZoom` style, which always sets `--zoom-grid`) it resizes the cards; anywhere else, or over `[data-zoom-ignore]`, it changes the UI scale (`CtrlWheelZoom` in App.jsx, 80 to 150% in 5% steps). Ratings use `ui/RatingPicker` (fixed heights, hover from pointer x) in RateGameModal, FinishedGameModal and the Edit Game window (an old decimal shows rounded, kept until a new pick).
- Library and Game List have only Big grid and List views; the month filter lives in Play Plan.
- The wallpaper (`Wallpaper` in App.jsx) is fixed behind the whole window; with it on, `.app-main` and the sidebar turn see-through.
- Resource rules (keep them): autoBackup only writes after `markDirty()` (30 min safety net); idle process scans relax 20s → 45s after 10 quiet minutes; one PowerShell helper in total (desktopProbe), never a new one during a game; in-session Steam Web API polls every 60s when `steamStatsWatcher.isWatching(game)`; Steam caches go through `capSet`; stored covers are shrunk to 600 px wide (`steamApi.shrinkCover`). Renderer: `html[data-inactive]` pauses every animation and trailer while KoZo is hidden, unfocused or not the app in front (with a -60s delay, so one-shot fade-ins sit on their visible last frame instead of an invisible first one). Focus events alone can't set it: a window opened while a game has focus never gets a blur, and drew behind the game at about 14% of a core until `app:inFront` was added; gamepad polling starts only after the first `gamepadconnected`; no `backdrop-filter` on repeated chips; wide calendar art uses the 616px capsule (hero only for Featured).
- Remove from library offers Keep history (`games:archive`) or Delete with history (`games:delete`, accepts an id or array, also deletes the banner/hero files).
- Card grids size their columns from `--card-min` (`ui/CardSizeSlider` on Library, Game List, Finished and Discounts, Ctrl + mouse wheel everywhere, via `lib/useCardZoom.js`, saved per page and view). Keep new grids on the same variable.
- Library and Game List toolbars never wrap (`.oneRow`, a container query on the toolbar): the search, dropdowns and slider shrink, the secondary buttons fold to icons, then the title goes. A wrapping row breaks on each item's starting width, so it can't be tuned to stay put. A rule hiding the composed `.pageTitle` needs extra specificity, or the composed one can win by load order.
- Automatic covers go through `steamGridDb.matchGame`, never the search's first hit: "Command and Conquer Generals Zero Hour" answers with the 1995 game. Pure `bestMatch` wants 60% of the words shared, else no cover (a generated one beats a wrong one); the search can miss a game by its full name and find it by its last words, so those are tried too. Scan PC reads hyphens for spaces only with two or more (`tidyFolderName`: "Half-Life" stays); a one-time step (`folder_names_v1`) renamed games already named that way and looked their covers up again.
- Deleting a game (`games:delete`) deletes its Game List row when the row has nothing left to show (`gameListQ.isBlankRow`); a row with a Steam id, art, a rating, a plan or an alert stays and keeps the game's Steam id and link. Name-only rows the user added stay: only a one-time step (`purged_junk_list_rows`) removes blank rows named like junk folders ("Redist").
- The Game List window has one way into editing, its Edit tab: no Edit button in the footer (the user's call).
- Background color: `lib/bgTone.js` maps every pick to a different dark shade (lightness 4 to 16%, saturation up to 55%), and `ColorPicker`'s `resultOf` makes its box show the color really used. The user chose this over real bright backgrounds. The Custom theme's quieter text colors are a step lighter to stay readable on the lightest shade.
- A status is not a state of the game: the game page's button reads "Status: Playing" with a gamepad icon (`LIBRARY_STATUSES`), and a play triangle only ever means start.
- Discount cards say "Close to your taste" (35%, the filter's line) or "Near your taste" (20%), nothing below, and the score reads N/100. A percentage read like something bad.

- The Alt+J achievement list over the game was removed on the user's request; don't bring it back.
- Windows reports a file being READ as an `fs.watch` "change" (no new modified time or content), so any watcher must compare content. KoZo reads its own files as it starts, so the dev runner used to restart itself up to seven times in a row.
- Achievement icons on Steam's old servers (`steamcdn-a.akamaihd.net`, `cdn.*.steamstatic.com` under `/steamcommunity/`) can answer 404, and Steam's API still returns those links. `db/achIcons.js` moves them to `shared.fastly.steamstatic.com/community_assets/` when written (`bulkUpsertAchievements`), and a one-time migration fixed stored rows. Use `ui/AchImg` to show one.
- Steam's store search sometimes answers 200 with no items for a search that has 25 a moment later, so `searchGames` retries an empty answer. Its guessed `header_image` 404s for newer games, so show `capsule` first or fall back (`HitArt` in GamesLike).
- `SteamGameModal` shows no media until Steam answers, because the art alone would be replaced by the trailer a moment later. Trailers start muted (`kozo:trailer:muted` remembers a choice).
- Testing a SteamGridDB key must use a never-seen request (`testKey`): Cloudflare answers popular ones (`/search/autocomplete/portal`, `/grids/steam/400`) from cache with 200 for ANY key.
- Upcoming's feeds and store records are also on disk (`upcoming-cache.json`, userData): up to a week old they show at once and refresh in the background, and `steamApi.warmUpcoming` fills them after launch. `getAppAssets(ids, { allowStale: true })` is for this page only; art downloads use the strict 24h rule.
- "N games protected" only counts games with a backup; before the first one it says waiting, and the shield has no check.
- The Edit Game window: the cover and name, game file and folder in view; everything set once under More options, whose closed row says what it's set to. Short labels, a hint only where it's needed. Keep it that way: it was called bulky when every option had a paragraph.
- Settings > Backups stays short on purpose: one status card, two closed folds, and the choices in pop-ups (Set up, Get everything back). Add new options there, not to the page.
- A session under 60s ends with `session:discarded`, not `session:ended`: anything showing a live session must listen to both, or its timer runs forever.
- The Google client reaches release builds through GitHub secrets (`electron/defaults.local.js`, gitignored, written by `release.yml`), because the repo is public. Missing secrets stop a release, because 1.9.0 shipped without them and nobody but the maker (who has a client pasted in Settings) saw Google sign-in. To check a published build, read `electron/defaults.local.js` inside its `app.asar` (the 7z inside the installer is stored uncompressed). See `docs/google-drive.md`, including what brand verification needs.
- CheapShark prices are US dollars only, and Epic appears only for games it lists (3 of 25 sampled). Epic's own price services refuse outside requests (checked: 404 and 403), so don't look for another route without a new reason. Compare stores with Steam only in the US (`elsewhere`); elsewhere they're labeled as US prices. IsThereAnyDeal has prices by country but needs a key, and the user chose CheapShark. Steam ids are looked up 25 per call with `storeID=1` (one row per game, on sale or not) and kept on disk, so nearly every deal has a lowest price (186 of 191 measured; two pages of deals found 10).
- A price alert's amount means nothing in another currency, so it stores the country and is ignored (and says so) elsewhere. `moneyText` writes an amount in the format of a price Steam wrote: Steam's cents are always the price times 100, also for currencies with no decimals.
- The smoke test also runs on GitHub's machine before every release, with a small screen and no user at it. `innerText` reads text as drawn, so a heading with `text-transform: uppercase` comes back in capitals: match without case. Don't check exact on-screen sizes: windows shrink to fit the screen and open with a scale animation (use `offsetWidth`, and compare to the room there is). A failure there stops the release, so nothing is published.
- `scripts/smoke-test.js` points `documents` at its throwaway folder, and `chooseBase` honours `KOZO_SMOKE`. Without both, a local run adopts the real KoZo Backup folder.
